# Glossary

Generated by `zag emit` from the concept system in `src/knowledge`. Do not
edit this file: change the concept, and the definition changes everywhere it
is used, including in the product's own text checks.

## development environment

collection of tools and resources that a person or program uses to build and change software

## workspace

development environment that keeps its sessions, files, agents and history together and restores them after a restart

Also called: bench

Do not use: project shell

Do not use: environment group

## session

workspace part that runs one program under one working directory and records everything that program produces

## block

record of one unit of work that holds its request, its output, its result and the conditions it ran under

Also called: command block

## workspace event

typed statement that something happened in a workspace, written once and never changed

Also called: event

## event log

ordered store of workspace events in which each entry carries the hash of the entry before it

## actor

party that can cause a workspace event, whether a person, a program or a service

## agent

actor that plans and carries out work in a workspace on behalf of a person, using tools it is allowed to use

## tool call

single typed request from an agent to do one thing, together with the result of that request

## capability

named permission to perform one class of operation, such as reading files or opening network connections

## policy

rule set that decides whether an actor may use a capability on a resource, and whether a person must approve first

## authorisation decision

record of one policy outcome, naming the actor, the capability, the resource, the result and the reason

## approval

decision by a person to allow one operation that policy would not allow on its own

## artefact

durable thing the workspace can name and describe, such as a document, a dataset, a patch or a report

Also called: artifact

## provenance

account of how an artefact came to exist, naming its producer, its sources, its tools and the time it was made

## record

artefact kept as evidence of an activity, held unchanged for as long as its retention rule requires

## evidence

record that shows whether one requirement was met, naming the method used to check it and the result

## standard

published document that states rules the workbench applies to its own behaviour and output

## requirement

single checkable rule taken from a standard, with a scope, a verification method and a severity

## conformance profile

named selection of requirements that applies to one kind of work, such as scientific writing or legal communication

## audience

group of readers whose purpose, prior knowledge and reading conditions decide how content must be written

## plain language

way of writing in which the intended reader can find what they need, understand it and use it the first time they read it

From: ISO 24495-1

## concept

unit of knowledge created by a unique combination of characteristics

From: ISO 704

## term

word or phrase that designates a concept in a subject field

From: ISO 704

## data element

registered field with one meaning, one value domain and one canonical name across every interface

From: ISO/IEC 11179

## dataset

collection of data prepared for one purpose, with a stated lifecycle stage, quality profile and retention rule

## pseudoterminal

pair of connected devices that lets a program behave as though it were attached to a terminal

Also called: PTY

Also called: pty

## terminal surface

workspace area that draws terminal output and sends key presses straight to the running program

## shell integration

set of markers a shell sends so the workbench can tell where a prompt, a command and its output begin and end

## worktree

checked-out copy of a repository at one branch, which a session can use without disturbing other sessions

## execution graph

set of workspace events linked by cause, showing which action led to which result

## workflow

task graph whose nodes declare their inputs, outputs, permissions, cache key and failure behaviour

## knowledge base

workspace store of rules, prompts, workflows, notebooks and vocabulary held as ordinary files under version control

## risk

effect of uncertainty on an objective, recorded with its source, its likelihood, its impact and how it is treated

From: ISO/IEC 23894

## impact assessment

record of how an AI system may affect people and organisations, and what the operator does about it

From: ISO/IEC 42005

## metric

measure with a defined unit, period, source and comparison basis, reported the same way every time
